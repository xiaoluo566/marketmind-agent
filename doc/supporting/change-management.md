# 变更管理

## 规则

- 每个阶段都要有可运行版本
- 每次大改动前先做文档更新
- 先提交小步可回退版本，再做下一步

## 建议分支

- `main`：稳定版本
- `dev`：日常开发
- `feature/*`：阶段性功能
- `hotfix/*`：紧急修复

## 标签

- `v0.1-docs`
- `v0.2-mvp`
- `v1.0-demo`

## 变更等级

### 低风险

- 文档补充
- 测试补充
- 日志字段新增

### 中风险

- API 字段变化
- 数据模型新增字段
- Agent 工具新增

### 高风险

- 数据库迁移破坏兼容
- 任务状态机变更
- 部署方式变化
- 模型输出 schema 变化

## 高风险变更要求

- 先写变更说明
- 创建功能分支
- 补测试
- 明确回退方式
- 合并前检查 `release-checklist.md`
