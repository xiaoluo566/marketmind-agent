# 项目章程

## 项目名称

MarketMind Agent：电商评论洞察与证据链报告 Agent。

## 项目目标

把“输入商品链接、Demo Dataset 或评论 CSV/JSON -> 自动采集或导入评论 -> 结构化清洗与语义检索 -> 生成带证据链的运营分析报告”做成一个完整闭环，并且具备工程化、可追踪、可回退、可扩展的特征。

## 目标用户

- 想快速分析竞品评论和用户痛点的电商运营
- 需要把差评证据转成产品改进/机会点报告的分析人员
- 想训练工程化 Agent 项目的开发者
- 面试中需要展示后端、异步任务、RAG、Agent 状态机能力的学生

## 典型场景

用户输入一个商品或竞品链接，系统异步采集商品标题、价格、评论、评分等信息。采集完成后，系统清洗评论，把长文本切片并向量化。Agent 根据任务目标调用检索工具，找出高频差评、用户痛点、潜在卖点和风险，最后生成一份带证据链的评论洞察报告。

另一个场景是爬虫失败或目标站点不可用。系统允许用户上传 CSV / JSON 作为兜底数据源，仍然能走完整的数据清洗、RAG、Agent 分析和报告生成链路。这样项目不会被单一站点反爬卡死。

## 核心价值

- 让用户不用手动翻几十个页面和评论
- 让 Agent 能在长任务中保留状态，而不是只靠内存
- 让每一步推理、每一次工具调用、每一次失败都可追踪
- 让报告里的判断能回溯到评论、页面或工具输出
- 让项目可以通过 Git、文档、测试和指标持续演进

## 非目标

- 不替代 Helium 10、Jungle Scout、卖家精灵等成熟卖家工具
- 不做销量预测、关键词投放、广告优化或库存管理
- 不追求全网爬虫覆盖
- 不追求一开始就多服务微服务化
- 不追求“无限自治”的复杂 Agent
- 不追求重前端或高视觉表现
- 不做绕过登录、验证码、付费墙或网站安全策略的采集
- 不把没有证据的数据写进报告结论

## 交付标准

- 能提交任务
- 能异步执行
- 能显示进度
- 能生成报告
- 能重试和回退
- 能统计耗时、错误率和成本

## 成功判定

- 单次任务链路闭环可跑通
- 关键状态落库
- 失败原因可复现
- 项目结构适合继续迭代 3 个月以上

## 简历含金量判断

这个项目要避免变成“调用大模型写报告”的薄 demo。真正有价值的点应当集中在：

- 长任务异步解耦：API 返回 task_id，Celery 后台执行
- Agent 状态落库：Thought / Action / Observation 可回放
- 数据证据链：报告结论能追到原始评论或页面
- RAG 工程化：评论切片、向量化、语义检索、召回证据
- 稳定性设计：重试、失败分类、断点续跑、结构化校验

## 市场定位边界

本项目的商业口径不是“大而全卖家工具”，而是“评论洞察和证据链报告工作台”。成熟卖家工具通常覆盖关键词、销量估算、广告、库存和利润分析，本项目第一版只聚焦评论数据中的用户痛点、产品缺陷和机会点。

这样定位更利于落地：一方面真实运营确实需要快速分析大量评论；另一方面第一版也不会因为缺少销量估算、广告数据或全站点采集能力而被质疑范围过大。
