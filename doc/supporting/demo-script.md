# 演示脚本

## 演示目标

用 5 到 8 分钟展示项目不是玩具 demo，而是有完整工程链路的 Agent 系统。

## 演示数据准备

为了避免正式演示时受目标站点影响，需要准备两套数据：

- 实时采集样例：展示 Playwright 能采集真实页面
- 固定 CSV / JSON 样例：确保即使网络或站点失败也能完整演示 RAG 和报告生成

## 推荐流程

1. 打开前端控制台
2. 输入一个商品链接或测试数据集
3. 提交任务，展示返回 `task_id`
4. 展示任务状态实时变化
5. 展示 Agent 步骤时间线
6. 展示采集到的商品和评论
7. 展示差评语义检索
8. 展示最终报告
9. 展示数据库里的状态记录
10. 展示一次失败重试或断点恢复

## 演示时要展示的页面

- 任务提交页
- 任务详情页
- Agent 步骤时间线
- 差评检索结果
- 报告详情页
- 历史任务列表

## 重点讲解

- 为什么用 Celery 解耦长任务
- 为什么 Agent 步骤要落库
- 为什么评论要向量化
- 为什么输出要经过 Pydantic
- 为什么报告必须带证据链

## 最后展示

- 任务成功率
- 平均耗时
- 输出校验失败和修复次数
- GitHub commit 历史
- 数据库状态记录

## 演示失败时的备用路线

- 如果实时爬虫失败，切换到上传样例数据
- 如果模型接口失败，展示历史报告和已落库的 Agent steps
- 如果前端异常，直接用 API 文档和数据库记录展示主链路
