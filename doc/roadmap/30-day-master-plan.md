# 30 天总计划

## 总目标

30 天内完成一个可以演示、可以继续迭代、可以写进简历的电商竞品调研 Agent 系统。

## 总体原则

- 第 1 周先把地基打稳，不急着追求 Agent 智能
- 第 2 周把 Agent 状态机和工具调用做好，不做黑盒推理
- 第 3 周把评论数据变成可检索证据，不让报告凭空生成
- 第 4 周把系统包装成可演示、可回退、可复盘的工程项目

## 周验收门槛

### Week 1

能从 API 提交任务，由 Worker 后台执行，并完成一次采集结果入库。

### Week 2

能看到 Agent 的 Thought / Action / Observation 级别执行过程，并且模型输出经过 Pydantic 校验。

### Week 3

能对评论做向量检索，并生成带证据链的竞品分析报告。

### Week 4

能通过前端演示全链路，有测试、有部署、有指标、有版本回退。

## 依赖关系

- Day 01 到 Day 03 决定项目边界和数据底座
- Day 04 到 Day 06 决定任务系统
- Day 07 到 Day 09 决定数据采集
- Day 10 到 Day 12 决定 Agent 核心
- Day 13 到 Day 18 决定记忆、检索和报告
- Day 19 到 Day 22 决定可视化和可观测性
- Day 23 到 Day 30 决定工程质量和展示质量

## 如果时间不够怎么裁剪

必须保留：

- FastAPI + Celery + Redis 异步任务
- PostgreSQL 状态持久化
- Agent steps 落库
- 评论 RAG 检索
- 带证据链报告

可以延后：

- 多站点采集
- 前端高级交互和复杂动效
- 复杂权限系统
- 高级图表
- 多 Agent 协作
